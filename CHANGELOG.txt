2026-10-15 — Group library by game, suppress subprocess console windows
- Added src/backend/lua_meta.rs. It reads a `.lua` file and extracts the
  app id (from the single-argument addappid call) and the depot ids (from
  the three-argument addappid calls). No Lua is executed; the reader scans
  for the function name and reads the numeric first argument. That is all
  the library screen needs to group files correctly.
- Rewrote the grouping in src/backend/library.rs. Previously the app id
  was only recognised when Steam's local ACF metadata already listed the
  game, so `.lua` files for uninstalled games ended up as their own
  entries and every `.manifest` file became an entry too. The new logic
  is two passes: (1) parse every Lua file, take its app id from contents
  or from a numeric filename stem, and register a depot-to-app map;
  (2) assign every manifest to the app that owns its depot, falling back
  to Steam's installed-depot map, then to a standalone entry keyed by
  depot id. Steam metadata now only improves display names; grouping no
  longer depends on it.
- Added CREATE_NO_WINDOW to every Windows subprocess spawn in
  src/backend/steam.rs and src/backend/file_dialog.rs. The registry
  probe spawns `reg.exe` and the file pickers spawn `powershell.exe`;
  without the flag, Windows opens a console window for each call, which
  produced the string of black terminals that appeared whenever the
  library was refreshed.
- Cached the Steam root discovery in a OnceLock in src/backend/steam.rs.
  The probe used to run on every State construction and every library
  refresh, which meant three `reg.exe` calls each time. It now runs once
  per process. Combined with CREATE_NO_WINDOW, opening the application
  produces no console flashes at all.

2026-10-15 — Route imports to Steam active directories by default
- Changed default_settings() in src/backend/archive.rs to prefer Steam's
  active directories when a Steam installation is discovered:
    .lua files      -> <Steam>\config\stplug-in
    .manifest files -> <Steam>\depotcache
  When no Steam installation is found, the previous private local library
  under the user's application data folder is used instead, so the tool
  remains usable on machines without Steam.
- Added steam::stplug_in_dir() and steam::depotcache_dir() helpers so the
  two paths are produced from the discovered Steam root in one place.
- Relaxed the storage path validation. The two active directories are now
  accepted even though they sit inside a Steam installation, because those
  are the directories the tool exists to populate. Any other path inside
  a Steam root (game installs under steamapps\common, config subfolders,
  etc.) is still rejected, so a misconfigured path cannot write into a
  game installation.
- Existing path overrides stored in %APPDATA%\Locomotive\paths.conf still
  take precedence over the new defaults. Users upgrading from a previous
  build need to either delete that file once or update the paths from the
  Options screen and press Save storage paths.
- This change contradicts a sentence in AGENTS.md that said the tool
  "must not write to Steam's active directories". That sentence predated
  the decision to route imports there and should be updated to match the
  new behavior.
